# 天穹分配器

天穹分配器是仅供本模组简易管道与物流节点使用的无缓存物品、流体、FE 及当前版本受支持可选资源（如 Mekanism 化学品）路由代理。化学品走流体管道；受支持的 Mana 类资源走能量管道。它不暴露通用 Forge/NeoForge 能力，因此原版漏斗和第三方管道不会连接。从六个相邻方块开始，它只沿容器继续搜索。节点或管道从分配器哪一面访问，全部绑定容器就统一从该面查询能力；BFS 路径与游标不会改变访问面。空气、普通方块、该入口面无可用能力的方块及其他分配器都会截断分支。目标上限默认为 32 个，服务器可通过 `[distributor].maxTargets` 在 1–64 间调整。

输入资源默认会在当前可接收的目标间尽量均分。分配器接收到红石信号时会切换为顺序存放：从轮转游标开始尽量填入当前目标，再继续后续目标；断开信号后立即恢复均分。安装 Jade 后可查看当前模式。抽取会聚合全部目标，不要求均分。

每个实际接入面拥有独立目标缓存。放置时只预热已经相邻本模组管道或节点的面，其余面首次使用时惰性扫描，避免无条件执行六次 BFS。邻居变化会令全部面缓存失效，同时每 100 tick 做一次惰性能力变化保底校验。未完成的扫描会在后续 tick 继续，期间不会把已连接面误报为不可用。切换接入面会清除旧面的瞬时计划，但不会重置分配器共享的本 tick 传输预算。服务器可分别关闭物品、流体与能量联动，三种可选资源还分别受对应的 `allow...Transfer` 开关控制。

物品路由与线路采用相同的分层思想：线路把精确物品 key 路由到分配器，分配器再以同一 key 路由到内部机器。每个接入面默认保留 64 个 `ItemStackKey → 机器` 路由；已成功机器优先，未知或拒收机器按预算增量发现，因此多种严格输入设备稳定后不再为每种产物反复完整扫描全部机器。抽取则按机器保存同源的探测退避状态。成功探测会立即提升到热等级，连续失败依次降到温热、低频和兜底等级；默认间隔为 1、5、20、40 tick，每连续失败 3 次降一级，均可通过 `[distributor].itemTarget...` 配置。首次拒收且从未成功的 `key × 机器` 直接进入 40 tick 兜底；到期时仍会发现动态变化。多槽机器保留自己的成功槽位。物品插入的模拟阶段生成有界传输计划，执行阶段直接复用。`[distributor].scanOpsPerTick` 独立限制 BFS；`[distributor].opsPerTick` 限制传输探测，默认 64。两种预算都不与物流网络预算共享，预算耗尽时资源留在来源并在后续 tick 继续。

手持天穹配置器并将准星对准分配器，会以青色边框高亮当前缓存内的全部目标容器。客户端只在切换所瞄准的分配器时立即请求快照，持续瞄准时每 20 tick 更新一次；渲染不会逐帧扫描容器。

它通过工作台制作：四角放海晶石，上下放青金石，左右放紫水晶碎片，中心放红石比较器，无需祭坛、尤洛伽水晶或天穹石。
