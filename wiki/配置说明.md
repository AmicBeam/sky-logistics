# 配置说明

服务端配置决定世界规则与性能预算；客户端配置只影响本地显示。配置文件名会随加载器和版本略有不同，建议先启动一次游戏生成文件。

## 仓库

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `maxVaultTypes` | 36 | 甘露可扩展到的最大物品/流体类型数，范围 1–63 |
| `maxVaultItemEntryNbtBytes` | 8192 | 单个不同物品条目允许的最大序列化数据字节数 |
| `maxVaultFluidEntryNbtBytes` | 4096 | 单个不同流体条目允许的最大序列化数据字节数 |

## 传输与性能

下表中的单次传输上限与每 tick 操作预算是不同维度。可选的 [[AStages 联动|AStages联动]]和[[原版进度联动]]分别限制各资源的单次搬运量，不改变操作预算或工作频率；1.21.1 的坚守者灵魂拥有独立档位。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `transfers.nodeItemTransferLimit` | 2,147,483,647 | 普通节点[单次物品传输上限](AStages联动) |
| `transfers.nodeEnergyTransferLimit` | 2,147,483,647 | 普通节点[单次 FE 传输上限](AStages联动) |
| `transfers.skyContainerTransferLimit` | 9,223,372,036,854,775,807 | 支持 long 的存储端点之间[单次直连传输上限](AStages联动)（如天穹仓库、AE2、Beyond Dimensions） |
| `transfers.maxSpeedUpgradesPerNode` | 8 | 单个节点升级槽内可堆叠的槽位并行升级上限 |
| `orderedMatchingUpgrade.wrapTargets` | `true` | 逐槽模式在来源槽位数多于接收端数时，是否按槽位号对接收端数量取模；逐个模式游标始终循环 |
| `orderedMatchingUpgrade.continueAfterTargetFailure` | `true` | 当前目标拒收或暂不可用时，是否允许越过；逐槽会扣押对应槽位，逐个会在启用扣押时保留该单物品分配 |

| `transfers.performance.lineOpsPerTick` | 1,024 | 单线路每 tick 操作预算 |
| `transfers.performance.endpointTargetAttempts` | 4 | 一个来源候选每次最多尝试的目标数 |
| `transfers.performance.externalTankScansPerEndpoint` | 8 | 每端点每 tick 最多扫描的外部流体槽数 |

| `transfers.fillMaintainedItemSlots` | `true` | 按槽数维持任意资源时，达到目标存储单元数后是否继续填满已有匹配单元；保留旧字段名兼容既有配置，不影响按“个”维持 |

| `transfers.retryAndCaching.rejectedAcceptCacheSize` | 9 | 每个接收端点记忆的近期拒收记录数 |
| `transfers.retryAndCaching.transferRetryFirstTicks` | 5 | 第一次连续失败后的等待 tick |
| `transfers.retryAndCaching.transferRetrySecondTicks` | 10 | 第二次连续失败后的等待 tick |
| `transfers.retryAndCaching.transferRetryThirdTicks` | 20 | 第三次连续失败后的等待 tick |
| `transfers.retryAndCaching.transferRetryMaxTicks` | 40 | 第四次及以后连续失败后的等待 tick |
| `transfers.retryAndCaching.enableMaintainedItemHotSlotPolling` | `true` | 是否让经过非零物品维持值的路径把相关退避限制到维持退避时长 |
| `transfers.retryAndCaching.enableMaintainedFluidPolling` | `true` | 是否启用流体维持路径的退避上限 |
| `transfers.retryAndCaching.enableMaintainedChemicalPolling` | `true` | 是否启用化学品维持路径的退避上限 |
| `transfers.retryAndCaching.enableMaintainedEnergyPolling` | `true` | 是否启用 FE 维持路径的退避上限 |
| `transfers.retryAndCaching.enableMaintainedManaPolling` | `true` | 是否启用 Mana 维持路径的退避上限 |
| `transfers.retryAndCaching.enableMaintainedSourcePolling` | `true` | 是否启用魔源维持路径的退避上限 |
| `transfers.retryAndCaching.enableMaintainedSoulPolling` | `true` | 1.21.1 是否启用 Souls 维持路径的退避上限 |
| `transfers.retryAndCaching.maintainedItemHotSlotPollTicks` | 5 | 全资源维持路径的最大退避 tick；实际等待取 min(原退避, 本值)；保留旧字段名兼容既有配置，范围 1–1200 |

提高预算会增加大型网络吞吐，也可能增加服务器单 tick 开销。它与进度限流相互独立；建议一次只调整一个指标并观察 MSPT。

`fillMaintainedItemSlots` 开启时，节点存入面和项链维持模式达到目标存储单元数后，仍会继续填满已有匹配单元，但不会新开超过目标数量的单元。物品使用物品槽，流体/化学品/Souls 使用储罐，FE/Mana/魔源使用接收设备；关闭后达到目标单元数便停止补货。

一次抽取或存入路径只要经过任一非零维持值，该路径后续产生的端点失败、空槽/空罐、资源拒收以及分配器内部机器退避都会使用 `min(原退避, maintainedItemHotSlotPollTicks)`。字段名为兼容旧配置保留，默认上限为 5 tick；算法不再额外记忆或探测维持热槽，也不依赖接收端容量变化判断。流体、化学品、FE、Mana、魔源和 1.21.1 Souls 使用各自的独立开关。

## AStages

本节仅适用于 1.20.1 Forge 与 1.21.1 NeoForge。26.1.2 未声明 AStages 依赖，不支持该联动；即使兼容层遗留配置项出现在生成文件中，也不应启用。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `transfers.astages.enabled` | `false` | 是否启用按线路持有者 stage 限制单次搬运量 |
| `transfers.astages.initialRates` | 资源字典 | 未解锁 stage 时各资源上限；1.21.1 额外支持 `souls` |
| `transfers.astages.stageRates` | `[]` | stage 解锁字典列表；除 `stage` 外各资源字段都可省略，1.21.1 可填写 `souls` |

完整格式、多人线路归属和计算规则参见 [[AStages 联动|AStages联动]]。

## 原版进度

所有支持版本都可使用，不需要额外模组。线路持有者在线时读取其当前 Advancement 并刷新世界存档快照；持有者离线时使用最近一次持久化快照，尚无快照、无法确定持有者或查询失败时使用初始档位。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `transfers.advancements.enabled` | `true` | 是否启用按线路持有者完成的原版进度限制单次搬运量及“天穹物流”进度链 |
| `transfers.advancements.initialRates` | 资源字典 | 未完成任何已配置进度时各资源上限；1.21.1 额外支持 `souls` |
| `transfers.advancements.advancementRates` | 内置七档 | 有序进度解锁列表；每项配置 `advancement`、`icon`、`title`、`frame` 和资源速率，速率可填正整数或 `"unlimited"` |

完整格式和计算规则参见[[原版进度联动]]。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `maxTargets` | 32 | 单个分配器最多连接的容器数，范围 1–64；提高后会增加扫描与代理操作开销 |
| `scanOpsPerTick` | 16 | 单个分配器每 tick 最多检查的 BFS 位置数，范围 1–4,096；只用于目标发现，不占用网络或分配传输预算 |

## 第三方联动开关

AE2、精致存储、Beyond Dimensions、Mekanism、Botania、Ars Nouveau 和 Industrial Foregoing: Souls 的资源路径都在 `transfers.integrations` 分类下拥有独立 `allow...Transfer` 开关。关闭某一路径只禁用该资源联动，不会卸载方块或破坏已保存的网络。

`transfers.integrations.hideSkyWrenchWhenAe2OrRefinedStorageLoaded` 默认为 `true`。安装 AE2 或精致存储时，它会让天穹扳手从本模组创造栏中隐藏；设为 `false` 可恢复显示。无论开关状态如何，物品都会保持注册且配方始终存在，以兼容已有世界并避免配置热重载后物品与配方状态不同步。

强制抽取升级没有单独的启用开关。物品会保持注册表稳定；`transfers.integrations.forceExtractionUpgrade.deviceModIdWhitelist` 动态列出允许生效的设备方块 modID，默认仅包含 `mekanism_extras`。列表中没有任何已安装模组时，该物品会从创造栏和 JEI 隐藏，供奉配方也不会匹配；列表为空时同样禁用。

常见示例：

- `allowAe2ItemTransfer` / `allowAe2FluidTransfer`
- `allowRefinedStorageItemTransfer` / `allowRefinedStorageFluidTransfer`
- `allowBeyondDimensionsItemTransfer` / `FluidTransfer` / `EnergyTransfer`
- `allowFluidChemicalTransfer`
- `allowFluidSoulTransfer`（1.21.1）
- `allowEnergyManaTransfer`
- `allowEnergySourceTransfer`

外部接口的完整开关为：

- AE2：`allowAe2ItemTransfer`、`allowAe2FluidTransfer`、`allowAe2AppFluxEnergyTransfer`、`allowAe2AppliedMekanisticsChemicalTransfer`、`allowAe2AppliedBotanicsManaTransfer`、`allowAe2ArsEnergistiqueSourceTransfer`；1.21.1 另有 `allowAe2SoulpliedEnergisticsSoulTransfer`
- Refined Storage：`allowRefinedStorageItemTransfer`、`allowRefinedStorageFluidTransfer`
- Beyond Dimensions：`allowBeyondDimensionsItemTransfer`、`allowBeyondDimensionsFluidTransfer`、`allowBeyondDimensionsEnergyTransfer`、`allowBeyondDimensionsMekanismChemicalTransfer`、`allowBeyondDimensionsSourceTransfer`；1.21.1 另有 `allowBeyondDimensionsSoulTransfer`

三种接口的用途、前置与过滤限制参见 [[外部网络接口]]。
